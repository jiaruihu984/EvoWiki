# EvoUI：进度和结果

- 读者在块里的操作（控件的值、选过的答案、检查过没有）会自动保存，下次打开接着上次的样子；每次检查答案的
  结果也会自动记下来（哪题对、哪题错、用了多久）。不用为此写任何东西。
- 宿主（网页、Obsidian 插件）注意：`onQuizResult` 和 `results().answers` 只带单选 / 判断题的答案；多选题的答案是
  序号列表，只通过结果事件（`onEvent` 的 item 事件）送出，要记录多选题就必须转发 item 事件。
  每个结果事件都带 `session`（这次渲染随机生成的 16 位十六进制）：没恢复进度的新渲染里轮次和 revision 会从头算，
  服务端按 `session` + 节点 + 题 + 轮次 + revision 判断是不是重发，所以新渲染的作答不会被当成重复丢掉；
  同一个 `session` 重发的事件仍然只记一次。不带 `session` 的旧客户端照旧按节点 + 题 + 轮次 + revision 判断。
- 一页一题的测验会记住做到第几题、选过什么、提示开没开、第几轮，下次打开接着做；每判一题就记一次结果。
- 闪卡会记住这一轮的顺序、看到第几张、翻没翻面、哪些没记住和每一步（撤销用），下次打开接着看。
- reveal 记住揭开了几步；计时器记住用了多久（重新打开时是暂停的）；播放器记住速度（重新打开时不会自己播放）。
- 填空和拼句记住这一次选了什么、第几次尝试；翻页器记住翻到第几页、完成没有；选择路线记住选了哪个。
- 小程序（`app`）的进度是它自己用 `evowiki.save` 存的内容，加上做到第几轮。
- 有状态的学习节点（`quiz`、`flashcards`、`reveal`、`timer`、`player`、`fill-blank`、`sentence`、`pager`、`route`、`app`）可以写 `id`：小写字母 / 数字 / `-` / `_`，1–32 个字，同一个块里不能重复。
  不写也行（按出现顺序编号）；块以后可能改写、增删节点时，写上 `id` 能让旧的进度和结果对得上。
