# 可视化与交互

三种用处：
- 看懂：看不见的东西画出来，动手就能看到它怎么变。
- 练熟：回想、计算或练习，掌握需要记住或会做的内容。
- 辨析：在具体情境里区分容易混淆的概念或做法。

规划时填 visual_questions。规划中已经确定要做的交互应当完成；做到一半发现没用，先改规划。

## 看懂：draw_visual
每写好一段，可视化那一步会判断它要不要画，结果在 write_section 的返回里。要画的段调用 draw_visual，并在正文里放占位符、前后告诉他看什么；它会自己决定形式，打开、操作、看截图。一段只画一次，要改用 revise。
规划里的 visual_questions 只是建议。没画成就用文字讲清楚。图和正文对不上时，改正文或改图，不能两边各写各的。

## 练熟、辨析：声明式的块
EvoUI 的结构和参数以 evoui 参考为准，只读实际要用的那一类。不得编造不存在的组件。- 记忆类（假名、单词、公式符号、术语 ↔ 意思）→ 闪卡，翻完一轮接一组分页测验（evoui/flashcard）。
- 要会做的步骤（套公式算一个数、解一类题、换算流程）→ 先一个完整例题一步步揭开，再做同类新题、提示一题比一题少（evoui/reveal、evoui/practice）。
- 几个参数一起决定一个数、换算和计算器 → evoui/chart。
- 易混的概念或用法 → 分页诊断测验，每个选项的 feedback 点出它对应的误解（evoui/quiz）。
- 一组小练习、熟练度练习、让学习者选学法 → evoui/practice、evoui/reveal（计时）。
- 顺序本身就是要记的（历史事件、发展阶段）→ 时间线（evoui/timeline）。
- 正文略过、但有人想知道的推导、例外、来龙去脉 → 「深入一点」（evoui/timeline），只在真有值得展开的内容时用。

## 写好一个交互
每个交互必须说明：why——它解决什么理解障碍，或者帮助练熟什么能力；学习者应该怎样操作、观察什么；操作后的结果及其原因。
- 练习提供明确反馈；适合反复尝试的操作支持重新开始。
- 不能只用颜色传达信息。
- 每个块都有完整的 fallback，交互显示不了时仍能通过文字理解核心内容。
- 出处只标在小节正文里，不写进块和组件。
